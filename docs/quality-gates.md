# 技能质量检查约定

为维护者提供共同检查标准，不作为所有技能运行时的额外流程。按实际改动选择检查，不机械执行全部项目。

## 按改动选择验证

| 改动 | 必要检查 | 何时扩展 |
|---|---|---|
| 描述翻译、界面文案 | 中文、语义与原触发边界、元数据格式 | 描述改变范围时补触发检查 |
| 路径、参考和结构调整 | 文件存在、相对链接、引用入口与按需加载 | 路由变化时实际完成一个取用任务 |
| 行为新增或实质修改 | 旧版/无技能基线、代表任务、相关边界与实际输出 | 新变化、失败或未解问题才重测 |
| 新增脚本 | 实际运行、相关正常/异常路径与代码评审 | 涉及外部状态时增加相应授权和回滚核查 |
| 动态解释或可视化代码 | 数据归属、计算与状态、关键控制、实际渲染和代码评审 | 涉及三维、依赖或窄屏时检查视角、降级和布局 |
| 安装或推送 | 差异、版本、备份、授权范围与写后读回 | 冲突或不同步时定位原因，不强制覆盖 |

## 结构与中文

- 业务技能位于 `skills/`，项目维护技能位于 `.agents/skills/`；二者每个目录都包含有效的 `SKILL.md`。
- 前置元数据的 `name` 与目录名一致，使用小写英文、数字和连字符；`description` 使用中文，明确具体任务与边界。
- 显示名称、短描述和默认提示使用中文；调用标识符、字段名、命令及正式名称保留原格式。默认提示含正确的技能调用标识符。
- `agents/openai.yaml` 存在时核对字段类型与策略；短描述遵守宿主当前长度要求。保留原调用策略，未经要求不增加外部依赖。
- 相对链接从所在文件目录解析。入口可找到必要参考，普通任务不会被要求读完整个资料库；不残留未完成脚手架。

当前宿主提供技能创建器时，定位其附带的 `quick_validate.py` 并运行；路径按实际环境获取，不把作者电脑绝对路径写进仓库。它只证明所检查的结构，不能代替语义、路由或行为检查。

## 场景与证据

场景覆盖与改动有关的显式、隐式或上下文请求，以及容易误触发的相邻请求。评估执行者拿原始任务和材料；评价标准与期望答案另存，避免只测到示例复述。

对每次实际运行记录：任务、版本、可读材料、实际动作与输出、观察、限制。记录“已通过”“未执行”“受阻”时须有对应事实；没有基线失败不宣称修复成功，不把一次行为通过当稳定率或学习效果。

结构检查、手工触发判断、宿主实际选择、行为输出和用户效果分别报告。前次的十二个论文场景不能冒充本次中文元数据调整的重新评测。

## 评审和发布

只评审时不修改文件；只设计时不自动创建或安装业务技能；只验证时不提交、不安装、不推送。用户明确扩展范围后，按授权继续，不重复请求已给的权限。

发布检查仅涉及目标改动：保留他人文件；排除私人材料；暂存后再检查；安装前保留旧版；推送后读回远程。工具不可用或远程未核对时明确受限，不伪造成功。
