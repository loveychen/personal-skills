# 新增与维护技能

每个技能放在 `skills/<skill-name>/`，一个文件夹对应一个独立技能。技能名使用小写英文、数字和连字符；目录名与 `SKILL.md` 中的 `name` 保持一致。

## 最小结构

```text
skills/your-skill-name/
├── SKILL.md
├── agents/openai.yaml   # 可选：显示名称与调用提示
├── references/          # 可选：按需读取的流程与参考
├── scripts/             # 可选：真正需要的可执行工具
└── assets/              # 可选：输出使用的模板或素材
```

最小 `SKILL.md` 示例，使用前替换名称及触发条件：

```markdown
---
name: your-skill-name
description: "用于这里明确描述的具体重复任务，说明触发条件、输入和不适用的相邻请求。"
metadata:
  version: "1.0.0"
---

# 技能标题

说明目标、必要上下文、关键决策、输出和能力边界。
```

先明确“什么请求应该触发、什么请求不该触发”，再写能改变助手行为的规则。主文件保持精简，复杂分支放参考材料；无必要不增加脚本、密钥或服务依赖。模板示例不能未经替换就作为正式技能提交。

关于触发写法、决策规则、渐进披露、证据与行为评测，见 [Skills 写作技巧](skill-authoring-practices.md)。本库的可复用测试场景放在 `evals/<skill-name>/`，避免被当成普通运行参考默认加载。

面向用户安装的技能放 `skills/`；仅帮助维护本仓库的技能放 `.agents/skills/`，不默认分发到全局。两类技能的描述、界面文案和默认提示都使用中文，字段名和稳定调用标识符保留原格式。日常维护入口见 [项目协作规则](../AGENTS.md) 和 [质量检查约定](quality-gates.md)。

## 提交流程

1. 在仓库源文件中编辑，避免只改助手的安装副本。
2. 按 [质量检查约定](quality-gates.md) 选择与改动相关的检查；语言小改不重跑整套无关业务评测，行为变化再检查实际输出和边界。
3. 按影响更新版本、技能目录和变更记录。外部技能改编需保留许可证与来源；仅概念参考也记录出处。
4. 检查将提交的文件，不包含论文全文、阅读记录、账号信息、密钥和安装备份。
5. 只有本次请求或有效上下文授权相应动作时，才提交、推送或同步安装；仅设计、只评审、仅验证的任务到约定交付为止。

以下命令用于已授权提交与推送的任务；未要求发布时不执行发布部分：

```bash
git status --short
git diff
git add skills/your-skill-name README.md CHANGELOG.md
git diff --cached
git commit -m "Add your-skill-name"
git push origin main
```

有未推送提交或分支冲突时先处理，禁止用强制推送代替正常同步。行为变化、新失败或未解风险需要相应重测；结构校验不能证明实际效果。

## 版本和回滚

每个技能独立记录版本。需要可重复安装某个历史状态时，可为仓库创建明确的 Git tag，并在安装时选择该 tag 对应的目录；先确认安装工具支持相应来源格式。

修改出问题时，仓库用 `git revert` 创建可审查的撤销提交并推送，本地安装按管理指南恢复备份或重新安装修复版本。不要直接改写已经共享的历史。
