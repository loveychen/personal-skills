# 技能验证与发布

先确定本次任务是**仅验证、同步安装、提交仓库还是推送发布**，沿用明确的用户授权；范围已清楚就直接做，不为每步重复确认。

## 验证

1. 读取工作区状态和目标差异，区分业务技能与项目维护技能，保留其他人的修改。
2. 按 [质量检查约定](../../../docs/quality-gates.md) 选择本次检查。验证器可用时实际运行；不可用时手工核对并如实标记，不能声称通过未运行的检查。
3. 需要行为检查时使用原始任务材料，保存实际输出与观察。历史通过只作背景，不能代替本次结果；来源无法访问或数据不足时保留未知。
4. 检查版本、中文文案、引用与变更记录。只验证的任务到此结束，交付通过项、未测项与必要下一步。

## 按授权同步

- 安装：只同步指定业务技能；核对现有副本差异，备份旧版，再写入并读回逐文件比对。项目级维护技能留在仓库内。
- 提交：仅暂存本次目标文件，检查暂存差异与隐私材料，避免把论文、断点或凭据带入源码。
- 推送：先核对远程变化，按正常快进或合并流程处理冲突，不强制覆盖；推送后重新读取远程提交验证。
- 任一环节受阻时继续不依赖它的检查，并说明具体状态。没有运行的步骤标为“未执行”，不要用“应该一致”代替比对。

## 完成交付

分别报告：**源码版本、实际验证及限制、安装状态、提交/推送状态、必要的后续动作**。用户只要求一项时只报告相关项，不扩成全套发布仪式。

具体安装、更新、卸载和回滚操作按需查 [管理指南](../../../docs/management.md)。
