# 怎样让结论既有依据，又能得到各方接受

本文是执行本技能时使用的本地方法摘要。主持人可以直接使用下文的问题、步骤和示例，无需先打开原书、论文或网页。原文入口、书目信息和实际阅读范围集中在[来源说明](sources.md)，仅在需要追溯或核对来源时查阅。

本参考把论证、检验和协商分开处理。三者解决不同问题：论证说明结论为什么成立，检验检查它可能错在哪里，协商寻找各方能够接受的具体安排。这个组合是本技能的方法设计，不是某一本书发布的统一流程，也不保证每个问题都有共识解。

## 1. 批判性讨论：主张需要经得起回应

Frans H. van Eemeren 与 Rob Grootendorst 在《A Systematic Theory of Argumentation: The Pragma-Dialectical Approach》（2004）中，把讨论组织为识别分歧、确定共同起点、展开论证和判断分歧是否解决等阶段。作者还讨论质疑权、辩护义务和举证责任。

本技能据此要求参与者指出争论的具体主张，明确共同接受的定义、事实和约束；提出主张的人应回应针对前提或推理的异议。把自己的结论当作前提、攻击角色身份，或让质询者证明一切相反命题，都不能消除原来的论证义务。

关键主张可以用一段完整的话表达：

> 依据是什么？这些依据为什么支持当前选择？推理还依赖什么前提？哪种情形会使结论失效？

主助手只需要为影响决定的主张补齐这些关系，不需要让每句话填写固定表格。参与者应准确理解对方最有力的论点，再回答它；主助手应保留原意，避免把较弱的替代表述当成对方立场。

## 2. 批判性提问：先找出值得追问的推理缺口

M. Neil Browne 与 Stuart M. Keeley 的《Asking the Right Questions: A Guide to Critical Thinking》（中文常译《学会提问》）围绕问题、结论、理由、歧义、假设、证据、替代原因、统计信息、遗漏和其他合理结论组织批判性思考。本次依据出版社介绍和详细目录，将其转成以下任务问题；这些中文问句是本技能的表达，不是原书引文。

| 值得检查的关系 | 角色可以怎样追问 |
| --- | --- |
| 问题与结论 | 我们要决定什么？这个结论回答了那个问题吗？ |
| 关键词的含义 | 各方说的“有效”“可靠”指同一种结果吗？ |
| 理由与隐含假设 | 从这些理由走到结论，还依赖什么事实判断或价值偏好？ |
| 证据质量 | 这是直接记录、个别经验还是他人判断？它能支持多大范围的主张？ |
| 替代解释与遗漏 | 其他原因能产生同样现象吗？哪些反面结果或重要信息没有被纳入？ |
| 其他合理结论 | 现有依据是否还支持范围更窄、条件不同或组合后的结论？ |

所有角色都应检查自己的主张，不能让怀疑者只负责反对他人。主助手应按重要分歧选问题，不要把这些问题变成每轮必须填完的问卷。发现术语不同或假设未成立后，角色应修改判断，主助手应修订受影响的方案，而不是只给推理贴一个错误标签。

例如，一方说“可靠”是指能够输出合规格式，另一方说“可靠”是指回答事实准确。两者不是已经证明谁对谁错；主助手应先澄清讨论的目标，再分别检查格式和事实。格式检查通过不能直接推出事实准确。

## 3. 严峻检验：检查必须有机会发现错误

Deborah G. Mayo 在《Statistical Inference as Severe Testing》（2018）第1.1节提出一项最低证据要求：如果方法即使面对错误主张也几乎总会给出支持，那么所谓“通过”缺少检验价值。

本技能借鉴这一排错原则。主助手应先问：如果主张错了，当前检查能发现什么？另一个方案或解释是否也会产生相同观察？哪些关键输入、失败情形或边界最可能暴露问题？观察到失败后，参与者应修改哪个判断？

例如，“两个版本各有一次成功”只能支持两次运行在相应范围内成功，不能区分哪个版本更稳定。主助手若要评价稳定性，应另行确定比较条件、样本与失败判据；没有条件时就保留该效果未知。静态检查也不能证明模型会自主作出相同决定。

这是对检验设计原则的定性迁移。本技能没有计算统计严重度，没有把案例推演等同于 Mayo 的统计检验，也不要求对价值判断计算显著性。验证力度应与所声称的结论相称。

## 4. 原则谈判：从各自立场走向共同方案

Roger Fisher、William Ury 与 Bruce Patton 的《Getting to Yes》（2011修订版）强调关注立场背后的利益、共同创造选项，并依据客观标准评价。哈佛谈判项目所属的 Program on Negotiation 公开材料将互利协商概括为澄清利益、构造选项和评价选项。

本技能据此要求角色说明“为什么坚持这个做法”及最低可接受条件。主助手可以寻找组合方案、不同适用范围或其他共同选项，再用已经认可的标准检查。参与者的历史投入、表达强烈程度和轮流让步，都不能自动成为选择标准。

这里的妥协是对可权衡偏好的调整，例如在满足准确性要求后接受更高成本。事实、用户硬性要求和未经满足的关键证据不能被协商成“已经成立”。各方不必给出相同的偏好排序，但必须明确接受同一安排及其代价。

## 5. 两种错误不能互相抵消

| 当前情况 | 主助手应怎样推进 |
| --- | --- |
| 所有角色都同意，但推理依赖未证实的关键前提 | 主助手应查证或收窄主张，不能以一致意见完成验收。 |
| 关键机制已有充分依据，但角色仍对方案有实质异议 | 主助手应查清异议保护的目标，构造或修订共同方案，不能替角色同意。 |
| 各方接受适用范围明确的设计，实际效果尚未知 | 主助手应检查该范围是否满足原设计目标，记录效果边界；主助手不能宣称效果已优于基线。 |
| 各方只同意将来做实验，用户要的选择仍未作出 | 主助手应继续解决决定障碍；试验安排不是最终选择。 |
| 必要条件彼此矛盾，或决定性证据超出授权 | 主助手应说明真实障碍及最小决定点，保持任务未完成，不能强造共识或越权验证。 |

主助手判断深度时，应看关键前提是否暴露、推理能否复查、强反例是否得到回应，以及这些工作是否改变或支持了实际方案。讨论篇幅、轮次数量和专业术语都不能替代这些证据。

这些来源支持方法选择，不证明本技能已经改善真实任务表现。科学论证与协商共识也不是同一回事；本技能同时设置两者的完成要求，源自本技能要解决的任务。
