# 辩论的执行细节

本参考保留特定运行条件下的要求。主持人只需读取当前任务涉及的小节；正文中的目标、辩论步骤和完成条件始终适用。

## Goal 与任务状态

主持人应把复杂辩论作为持续目标推进，维护同一份当前方案和累计状态。用户明确要求 Goal 模式、且宿主支持时，主持人应建立或关联原生目标，将实际交付和完成判据写入目标。

宿主不支持时，主持人应如实说明，使用可恢复的任务记录，不能声称原生 Goal 已启用。阶段报告、用完一轮讨论或提出试验计划，都不自动代表最终目标完成。

用户明确停止、暂停或宿主达到硬限制时，主持人应停止相应工作，如实交付未完成状态，并遵循宿主的目标状态规则。主持人不能为了结案把受阻写成目标完成。

## 角色怎样执行

主持人应依据有效目标明确需要确认的参与者及其代表范围，区分参与共识的角色与仅提供分析意见的角色。主持人不能为了结束讨论而排除必要反对方。参与范围确需调整时，主持人应保留与目标相关的理由和仍有效的异议，核对调整是否改变完成条件。

宿主和用户允许委派、且独立上下文有价值时，主持人应优先安排独立判断；并发有限时可以分批。

单个助手在同一上下文中分角色分析时，主持人必须说明意见不独立，不能把这些分析说成其他代理或真人已经给出的独立意见。宿主不允许或没有相应能力时，主持人可以使用这种分析方式，但不能绕过用户明确要求的独立执行条件。

用户明确要求独立角色而条件不满足时，主持人应说明限制，只继续获授权的准备工作，不能绕道委派。角色分析不能代替真实责任人的授权或认可。

## 怎样修订和比较方案

主持人应核实角色声称的“不可退让”究竟来自真实约束、利益还是未经验证的预测。真实价值冲突需要有权决定者选择时，主持人应给出具体选项、影响和推荐，不能把可自行查明的事实交给用户猜测。

主持人不能只让固定的甲乙丙方案反复争胜，也不能用“各退一步”代替说明新方案为什么有效。主持人不能只在末尾附加提醒，让相反旧规则继续生效，也不能把所有意见自动变成新需求。

比较候选时，主持人应使用相同目标、情形和判断标准。标准本身存在争议时，主持人应将该争议纳入讨论；各方不必先接受相同的偏好排序。用户看不懂方案差别时，主持人应使用同一具体场景解释，区分假设与实际观察。

## 查证与内部检索

问题涉及组织内部事实时，主持人应检查宿主是否提供获授权的内部检索能力，例如滴滴环境中的 SmartWork。主持人或获授权的参与者应按实际工具说明查证，保留来源、时间、适用范围和权限。

该能力不是安装或运行依赖。能力缺失时，主持人应使用其他获授权来源或说明未知，不能虚构检索结果。检索授权不等于公开、写入、发送或继续委派的授权。

## 怎样验证

主持人应根据要作出的结论选择证据：

| 结论涉及什么 | 需要检查什么 |
| --- | --- |
| 事实 | 主持人应核对相应来源、版本和适用范围。 |
| 逻辑或规则 | 主持人应检查前提、推导和反例。 |
| 模型或业务效果 | 主持人应取得相应运行证据，不能用设计推演代替。 |
| 价值偏好 | 主持人应说明取舍及决定权，不能靠实验宣布偏好为真。 |

主持人应先明确关键判断可能怎样出错、什么观察会要求修改结论。检查应有机会区分候选或排除重要替代解释；若方案即使错误也几乎必然通过，主持人不能把通过当作支持证据。

主持人应固定版本、输入及关键运行条件，区分静态检查、模拟、模型自行决策、真实服务和用户路径。多个因素同时变化时，主持人不能随意归因。现有实现更成熟，也不能证明其决策效果更好。

主持人应按风险选择必要验证。大规模或高成本运行前，主持人应先检查少量代表情形的完整路径和判定方法。检查应覆盖有力的反对意见、关键边界和相邻回归，而不只包含支持方案的成功案例。

证据不足时，主持人可以在原目标允许的范围内收窄结论，并请各方重新判断该结论是否仍能完成任务，不能自行降低验收要求。条件性方案只有仍满足原目标、关键条件已经落实或成为可执行的适用限制时，才可能完成设计任务。等待决定性证据后再作选择，仍然是未完成。

## 授权范围

用户要求设计或辩论，不自动授权部署、发消息、采购、付费模型或业务调用。主持人应始终遵守原任务边界。

调研、评测或发布流程不能代替实际方案。主持人不能因为讨论形成一致意见，就省略尚未完成的方案工作或自行开展未获授权的行动。
