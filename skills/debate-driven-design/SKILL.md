# 多角色辩论驱动的方案迭代

主助手担任主持人，组织不同角色一起解决有争议的问题。主持人最终要交付一份具体方案：各方明确接受它，它的理由和依据也经得起检查。

```text
主持人明确最终目标、完成条件与授权，准备当前方案和本轮问题。
循环：
    主持人检查停止要求和宿主限制；必要时保存真实状态并停止。
    相关角色针对当前方案和本轮问题，分别思考、质询和回应。
    主持人组织查证、修订和检验，记录本轮实际变化。
    主持人检查当前方案、证据和意见，判断离最终目标还差什么。
    如果方案满足目标且必要检查通过：
        主持人请需要确认的各方表明是否接受同一版方案。
        如果各方接受且条件已经落实：
            主持人交付要求的产物，报告完成并结束。
    如果仍有必要障碍，且当前权限内已经无法继续推进：
        主持人说明已尝试的方法、障碍和最小所需决定，报告未完成。
        主持人遵循宿主的目标状态规则，保留未完成状态并停止本次推进。
    主持人根据剩余问题调整提问与分工，带着当前方案和有效结论进入下一轮。
```


发现问题后，主持人应带着具体问题回到相关步骤。讨论过一轮、写完报告或安排好未来试验，都不等于已经解决了问题。

简单润色、单一事实核实和既定步骤可以直接处理。用户只要求局部讨论或阶段评估时，主持人应保留该范围，不扩大任务。

## 谁负责什么

主持人负责保持目标、安排讨论与查证、修订方案和交付结果。角色负责提出判断、回答质疑，并说明是否接受最终方案。

复杂争议默认覆盖以下五种视角：

| 角色 | 重点检查的问题 |
| --- | --- |
| 实践者 | 方案怎样实施？执行中会遇到什么障碍？ |
| 学者 | 概念是否清楚？研究和证据是否支持判断？ |
| 怀疑者 | 哪种反例会推翻判断？是否还有其他解释？ |
| 经济学家 | 方案需要多少成本？谁承担代价？激励是否合理？ |
| 历史学家 | 类似做法过去为何成功或失败？当时条件与现在有何不同？ |

主持人还应覆盖真正受影响的使用者或责任方。某种视角与问题无关时，主持人可以说明理由后省略。五种视角不要求固定五名代理，角色名称也不代表真实资历。

主持人应说明哪些角色需要接受最终方案、哪些只提供参考，不能为了结案而排除必要反对方。单个助手分角色分析时，主持人必须说明意见不独立。代理执行、参与范围变化和真实责任人授权的要求见[角色执行规则](references/execution-details.md#角色怎样执行)。

## 主持人怎样组织多轮讨论

主持人应根据讨论结果主动安排下一轮，不能只等角色自行争论。每轮都应围绕当前方案解决一个或一组关键问题：

1. **开始一轮前，主持人提出本轮问题。** 主持人应说明这个问题为什么影响最终目标、需要哪些角色进一步思考，以及应查明什么。首轮依据目标和初始方案提出问题，后续轮次依据上一轮结果提出问题。
2. **一轮结束后，主持人总结实际进展。** 主持人应说明本轮查清了什么、方案改了什么、仍有哪些分歧或未经检查的假设，以及离最终目标还差什么。
3. **目标尚未达到时，主持人选择下一轮怎样深入。** 主持人可以追问假设、补充证据、要求比较不同机制、检验反例，或重新构造方案。主持人应说明这轮要消除哪个障碍，不能只要求各方再讨论一遍，也不能诱导角色支持预设答案。

主持人应把当前版本、有效结论和新增材料交给下一轮相关角色，不必让所有角色每轮重写完整意见。新的证据可以推翻旧结论，主持人应保留撤回理由。即使各方暂时没有异议，主持人也应检查目标、关键前提和必要证据是否仍有遗漏。

轮数由剩余问题决定。满足完成条件后，主持人应组织最终确认，不为凑轮数继续讨论；没有实质进展时，主持人应改变提问或查证方法，并遵守后文的受阻与停止规则。

## 从明确问题到确认方案

第一步明确整个任务；第二至第五步可以根据主持人的安排重复多轮。第六步确认最终方案，确认时出现的新异议也可以成为下一轮的问题。

### 第一步：主持人明确这次要作出什么决定

主持人应从用户要求和已有资料中确定目标、结果使用者、完成条件、不可违反的要求，以及允许执行的范围。主持人应列出已有方案和关键争议，区分事实、当前实现、假设、未知和建议；已有标准时，主持人应核对版本和适用范围。

主持人应区分设计选择、效果判断和上线决定，分别核对证据与授权。主持人不能把用户要求的最终选择改成阶段推荐。用户改变目标时，主持人应同步更新方案和受影响的判断。主持人应持续维护同一份当前方案和任务状态；用户要求 Goal 模式时，主持人应遵守[Goal 与任务状态规则](references/execution-details.md#goal-与任务状态)。

### 第二步：各角色先给出自己的判断

主持人应给各角色提供相同的目标、约束、方案版本和必要原始材料。各角色应先分别回答：

- 你推荐什么做法？依据是什么？
- 你最担心哪种失败？
- 你想达到什么目标？你必须保留哪些条件？哪些偏好可以调整？
- 什么证据或方案变化会让你改变判断？

角色不必为了扮演某个身份而支持或反对。没有实质分歧时，主持人应检查共同依据和未知，不要求角色制造争吵。

后续轮次中，相关角色应针对主持人提出的新问题、当前版本和新增证据更新判断，保留仍然有效的认识，不从头重复首轮意见。

### 第三步：角色相互质询，并查明事实

主持人应把需要回应的意见交给相关角色。质询者应指出具体主张，并按当前分歧选择问题：

- 我们讨论的是同一个问题吗？关键词的含义一致吗？
- 这些证据为什么支持结论？推理依赖什么未说明的假设？
- 哪种反例会使结论失效？是否遗漏重要证据或其他解释？

角色也应这样检查自己的主张，不必机械问完清单。被质询者必须回答异议：接受意见、提供依据反驳，收窄或撤回原主张，或者说明还需要查明什么，不能只重复立场。对方尚未证明主张错误，不代表它已经成立；共同假设、角色数量和身份也不能证明事实。

主持人应安排相应查证：事实问题查阅原件，推理问题检查前提和反例，效果预测需要相应验证。真实价值取舍由有权决定的人选择；主持人不能让用户猜测本可自行查明的事实。

核实组织内部事实时，主持人应检查是否有获授权的检索能力，例如 SmartWork。该能力可选，缺失时不能虚构结果；来源记录和权限要求见[查证规则](references/execution-details.md#查证与内部检索)。

### 第四步：主持人把成立的意见写进方案

主持人应根据各方想达到的目标和能够接受的条件，寻找解决冲突的做法。主持人可以组合不同机制，或按不同情形制定规则，不必让原来的甲乙丙方案一直争胜。

角色可以调整偏好，但不能通过妥协改变事实、掩盖反例或取消用户硬性要求。主持人应将接受的修改落实到正文，说明改了什么、为什么改、还有什么异议。原方案经检查仍成立时，主持人可以保留，并说明理由和验证状态。

方案应写清执行者、动作、对象、条件和结果。比较候选、处理价值取舍及避免新旧规则冲突的要求见[方案修订规则](references/execution-details.md#怎样修订和比较方案)。

### 第五步：检查方案是否解决了原问题

主持人应先问：**如果关键判断错了，当前检查能发现什么？** 主持人应据此检查有力的反对意见和关键边界，同时检查改动是否让相关行为退步，不能只挑成功案例。

检查方式应匹配结论。资料可以支持事实判断，推演可以检查规则，但模型或业务效果需要相应运行证据。角色一致、预设正确输出或一次成功，不能单独证明效果提高。具体要求见[验证规则](references/execution-details.md#怎样验证)。

检查发现问题时，主持人应让相关角色回应，修改受影响的方案并重新检查。证据不足时，主持人不能自行降低验收要求。各方可以接受边界明确的设计，同时保留实际效果未知；“同意未来试验”不等于“同意采用方案”。

### 第六步：各方确认同一版方案

主持人应将同一份具体方案交给所有需要确认的角色。各角色应分别说明：

- 我接受、附条件接受，还是仍然反对？
- 我的理由是什么？我改变了什么判断或偏好？
- 我接受了哪些代价？哪些效果仍未得到验证？

附条件接受时，主持人应检查条件是否已经落实为方案条款。方案发生影响判断的变化后，受影响的角色应重新确认。主持人不能代替角色表示同意，也不能把沉默、多数票或共同约束当成方案共识。

## 遇到分歧后怎么办

| 当前情况 | 主持人应怎样推进 |
| --- | --- |
| 角色只重复原立场 | 主持人应澄清关键分歧、共同查证、检查反例，或提出新的共同方案。 |
| 决定所需证据还没有取得 | 主持人应在权限内继续查证。等待未来证据后再选，仍是未完成。 |
| 关键要求确实无法同时满足，或必要行动超出权限 | 主持人应说明已尝试的方法、具体障碍和最小所需决定，报告未完成。 |
| 用户明确停止、暂停，或宿主达到硬限制 | 主持人应停止相应工作，保存真实的未完成状态，并遵循宿主规则。 |

撤回错误论据、澄清误解和明确可接受条件都可以构成进展。增加角色、轮次或文档数量不构成进展；主持人不能无限重复讨论。

## 满足什么条件才能结束

主持人只有同时确认以下三件事，才能报告共识任务完成：

1. **方案解决了原问题。** 方案符合目标和硬性要求，关键推理有可核查依据，必要检查已经完成。
2. **各方接受了同一具体方案。** 接受条件已经落实，没有仍会阻止采用该结论的实质异议。
3. **要求的产物已经交付。** 方案写清必要动作、依赖、适用边界和验收方式，用户要求的报告等产物已经实际提供。

主持人交付时应先写最终方案和理由，再写主要质询与回应、实际修订、各方最后意见、验证结果和未知效果。角色共识不证明客观最优，也不能代替真实利益相关方同意。

## 需要时查阅哪些本地材料

执行本方法所需的规则、方法摘要和示例都保存在技能包内。主持人应按下面的用途读取本地材料，不需要为了使用本技能而逐一访问来源网页。

- 复杂辩论开始前，主持人应阅读[本地方法摘要](references/rigorous-consensus.md)，理解专业方法怎样指导质询、检验和协商。
- 涉及角色执行方式、Goal、内部检索、方案修订或验证时，主持人应阅读[执行细节](references/execution-details.md)中的对应小节。这些要求与正文同时适用；讨论形成共识不扩大用户授权。
- 需要记录复杂讨论时，主持人应阅读[一轮辩论的做法与示例](references/debate-round.md)。证据比较细节见[决策与证据参考](references/decisions.md)。

[来源说明](references/sources.md)用于追溯出处、核对阅读范围和延伸阅读，不是使用本技能的必读材料。用户要求阅读原文、来源解释存在争议，或当前任务确实需要核对原始论述时，主持人可以按任务及宿主规则查阅对应来源，不必打开全部链接。

这项约定只免去学习本方法时不必要的网页访问，不能省略当前任务需要的事实查证。本地摘要不足或已经过时时，主持人应说明缺口，并使用获授权的来源补充或核实。
