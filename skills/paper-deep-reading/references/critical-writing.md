# 批判性思考与阅读写作

用于讨论、阅读笔记、研究备忘录和证据校准后的段落，不把共读自动变成正式审稿。先解释作者真正解决的问题，再评估；评价直接、具体、公平，不靠负面语气显得深入。

## 先重建一个作者可认可的论证

明确 **问题 → 现有方法的限制 → 核心选择 → 预期机制 → 检验证据 → 结论范围**。把理论动机、实现改动、实验发现和作者解释分别放好。贡献可以是系统工程、测量或数据，不强迫每篇都提出新算法。

对关键结论检查“证据为什么能推出它”：例如 pass@32 较高，是支持候选覆盖率，还是支持部署答案正确率？更好的系统结果，如何支持某个 loss 的贡献？把这个连接写出来，才能发现跳步。

## 从观察到有用的质疑

选择会改变读者判断的少量问题，每项建立：

**主张/位置 → 可核对观察 → 影响结论的理由 → 合理替代解释与不确定性 → 能区分解释的证据。**

缺消融可能使归因未被隔离，不自动使系统成绩作废；预算不同可能是资源换性能，不自动是实验造假。假说、建议实验和已经完成的实验明确分开。新颖性质疑应比较最接近前作的实际机制与时间边界，不能写“只是拼接”而不给对照。

结论置信度说明来源：读了哪些章节/附录、核对了什么数学或设置、相关工作覆盖如何；不发明百分比或会议评分。证据充分时可以明确肯定，不强行找反方凑“平衡”。

## 校准措辞

| 证据状态 | 合适表达 | 避免 |
|---|---|---|
| 单次/有限协议观察 | “在所报告的条件下观察到……” | “全面证明通用能力……” |
| 有相关干预与对照 | “该对照支持……在这些条件下的贡献” | 把局部机制写成唯一原因 |
| 多因素一起变化 | “现有比较尚不能区分……与……” | “提升一定全来自……” |
| 报告缺项 | “节选/全文未报告……，因此无法核查……” | “作者肯定没有做……” |
| 有实质反例 | “该反例在满足前提时与……冲突” | 用违反前提的情景反驳定理 |
| 外部核验不足 | “目前未核验/覆盖有限，不能确认首次” | 凭熟悉程度断言没有前作 |

“可能”不能替代推理：说明哪种可能、影响什么、如何核查。避免“实验不足”“不够鲁棒”“创新有限”等没有对象的结论。相关性、机制解释、因果效应和部署建议不要写成同一层。

## 一个可用段落（合成例子）

> 该记忆系统在所测文档问答上报告了更高准确率，但它同时扩大检索候选范围并更新了索引[合成稿 §4 Table 2]。因此，结果支持整个配置在该协议下有效，却尚不能区分记忆更新机制与额外可检索信息的贡献；这不等于该机制无效。若要检验其独立作用，可保持同一模型、文档快照和检索预算，只改变记忆更新规则，再比较匹配问题上的差值与失败类型[建议实验]。在这些对照出现前，应将结论限定为所报告配置，而非一般性长期记忆能力。

段落承认贡献，指出实际观察，说明推论的限制，并给能改变判断的检查。不要机械复用这组缺点到其他论文。

## 按读者用途组织输出

- **解释/组会**：问题与价值 → 一条机制流程 → 一项关键证据 → 适用边界；用贯穿例子连接，不逐章转述。
- **批判性笔记**：准确定位 → 主张/证据与推论 → 最接近替代方案 → 当前判断与待解问题。
- **比较两篇**：先确定共同问题及不同信息/预算条件，再讲实质机制差异和可迁移想法；不要只是两份摘要拼接。
- **短段落请求**：直接交付连贯段落，少量必要引用；不为了模板添加全套表格、分数或问卷。

以上为可选结构。保持符号、译名和版本一致，减少夸大形容词；每段应新增机制、证据、比较、限制或研究含义。格式与字数听用户要求，不以写得长作为读得深的证据。
