# LLM、后训练与推理研究的阅读路径

按当前主张选检查点，先教懂再评价；不把整表一次交给初学者。下列是领域阅读框架，不是认定每篇论文都存在问题。

## 先确定贡献发生在哪里

沿真实流程还原：**数据/环境 → 起始模型 → 训练或提示 → 生成候选 → 搜索/验证/选择 → 输出 → 评分**。区分改了模型权重、推理流程、上下文，还是只改评测协议。先用原文一例贯穿流程，再下钻关键变化。

| 论文类型 | 先解释什么 | 关键检验 |
|---|---|---|
| 预训练/架构 | 表示、模块、数据与优化如何改变预测 | 数据构成/去重、训练 token 与 FLOPs、参数口径、容量和规模匹配 |
| SFT/偏好优化/RL | 数据来自谁、奖励/偏好如何转成参数更新 | 起始 checkpoint、数据与预算、online/offline、奖励/参考模型、是否隔离算法 |
| 推理时计算 | 谁生成、谁验证、谁选择、何时停止 | 样本/搜索/修订次数、长度、预算、oracle 信息、同预算或同质量比较 |
| RAG/长上下文/记忆 | 检索到的信息如何进入上下文、影响答案 | 语料/索引快照、检索与生成分开评价、信息权限、位置/长度、跨任务状态 |
| 评测/judge/可解释性 | 测量的能力和可观测证据是什么 | 样本与协议、评分有效性、污染、judge 偏差、解释的因果支持 |

尚未核对的参数写“待核验”，在实际已查材料中找不到才写“该范围未报告”，不要把缺项当已知违规。贡献类型可组合；用户研究目标决定是否精读训练或系统细节。

## 读懂目标函数，连接到一次更新

用一条训练样本或一个 prompt 的小例子解释：输入 → 候选/标签/奖励 → loss/advantage → 哪些参数变化 → 下次生成倾向。推理阶段另画一条线，不能把训练时多采样当部署必需，也不能反向混淆。

进入原式后，标出随机变量和采样分布、current/old/reference policy、reward/value model、哪些量冻结、token 与 sequence 聚合、mask、长度归一化、目标最大化还是最小化；只解释当前式子实际有的量。`old policy` 与 `reference policy` 可能职责不同，不因都不更新就合并。

对偏好/RL 论文追问：偏好来自人、模型还是规则？标量奖励衡量什么？reward 提高与真实任务完成是否一致？梯度是否穿过生成、奖励或参考模型？这些须看原文或代码，未知不能猜。归一化分母为零、截断输出和 token mask 等条件仅在会影响解释时展开。

**教学抓手**：先预测“更偏好某候选应如何改变其相对概率”，再核对原式符号和梯度方向。DPO、PPO、GRPO 等名称是定位线索，不能代替读取该论文/版本的定义。跨版本实现差异单独标记。

## 能力、预算与选择器

说明比较单位：同一 checkpoint 的方法消融、不同模型的系统结果、同预算性能，还是同质量成本。更新底座、更多训练数据、更多候选和更强验证器一起改变时，总成绩不能归因于单个 loss 或“更会推理”。

- 记录模型 ID/版本、prompt/few-shot/chat template、解码设置、截断、样本数、搜索/修订及失败重试；关键设置优先，非全量填表。
- 区分 greedy/采样单次、pass@k、majority vote、verifier-selected 和 oracle best-of-k。候选中存在正确解，不意味着部署选择器能选出；论文用了哪个定义就核对哪个。
- 必要时检查等生成 token、等总 FLOPs、等时延、等价格或等质量口径；它们并不等价。计入采样、verifier、搜索、难度估计、工具与重试；分离训练成本和推理成本。
- “compute-optimal”须说明相对哪组策略、预算及先验。测试答案、oracle 难度或未来信息只用于分析时，不能冒充可部署控制器；估计这些量的开销是否计入也要核对。
- 任务级成功概率不同，平均 pass@1 不能直接推出全基准 pass@k 或连续成功率。仅在明确同一任务的独立同分布假设下可用简单概率教学公式；不要以它代替论文估计器。

## 评测的解释范围

1. **任务与评分**：基准版本/split、完整题目分母、prompt、答案抽取/解析失败、单项与平均聚合。区分答案正确、格式合规、人类偏好与过程正确。
2. **信息边界**：检查训练、SFT、奖励/验证器/提示调优与测试的接触路径。闭源训练数据不透明应记为未知，不能断言清白或污染。RAG 合法检索允许的公开知识，不自动等于作弊；需看评测声称的输入权限与泛化目标。
3. **judge**：模型/版本、rubric、参考答案、顺序是否交换、长度影响、自偏好、平局/解析失败处理、与独立人工或可执行结果的校准。judge 同意率不等于客观真值，不把既有论文的偏差百分比套给当前系统。
4. **机制与稳健性**：选取失败例、改变提示/数据分布、边界任务；漂亮 CoT 可以是有用的可见行为，不能单凭流畅文本断言忠实解释内部计算。干预证据能支持哪些因果关系须单独说清。
5. **不确定性**：区分题目间差异、seed/采样随机性与模型/API 漂移；比较最好使用匹配题目的差值与适当不确定性估计，不能把同一题多次回答当独立新题。

本框架依据的原始研究与工程资料见 sources.md。具体论文结论仍须核对该论文，不从这里“继承”一个成绩或失败判断。
