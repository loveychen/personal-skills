# 对话与分层教学

## 调整深度

| 读者反馈 | 下一步 |
|---|---|
| “完全没懂” | 找出最早断开的概念，换成可算的小例子；不要同义改写一大段 |
| 术语卡住 | 补一个理解当前主线必需的概念，说明它在论文哪里起作用 |
| 结论对、理由错 | 区分结果与理由，修正关键连接，再给相邻情境 |
| 复述正确 | 说明正确之处；可用边界例子检验迁移，或按意愿继续 |
| “继续/快一点” | 推进下一台阶，减少确认；不登记为掌握 |
| “直接讲/别考我” | 直接讲解和示范，不以答题作为继续条件 |
| “详细推导/完整报告” | 放宽单轮篇幅，提供要求的完整内容，保留证据规则 |
| 提出支线问题 | 先回答；若会显著扩展，说明与主线关系，记录返回点 |

## 一个教学单元

围绕“问题—直觉—原文机制—后果”讲清一件事。短轮通常几段即可；完整证明可以更长。一次只引入完成该单元需要的符号与前提；保留论文术语，必要时中英对照，不强行翻译约定俗成名称。

读者只懂聊天模型时，先讲一个工具调用或一次“生成—选择”的区别；即使原文列了很多模块，也不一轮全展开。把未知背景视为可调整的起点，不能把“跟进 AI 论文”理解成已经熟悉 RL、统计或系统评测。

解释后选择一种有价值的参与方式：复述设计动机、预测删模块/改参数的后果、补推导中一个连接、构造反例，或比较两个方法的假设。给足完成任务需要的前提。

提问服务于理解。读者已说不会，就补讲，不把同一问题换个说法继续追问。没有回答时不宣布其理解；不要先给答案再把简单赞同算作独立掌握。宿主提供专用提问工具时按宿主规范使用；每轮选择一个主要问题，避免并行问卷。

## 纠错示例（合成教学情境）

读者说：“32 个答案里有一个对，所以最后给用户的答案也一定对。”先肯定其识别了候选覆盖，再纠正选择环节的跳步：**生成到正确答案，与识别并交付正确答案，是两件事。** 用两个候选、一个不完美评分器举例，标为教学例子；指回论文真实的候选和选择设置。不要因此断言 verifier 无效，也不要把 oracle 选择当实际工具。

视意愿邀请预测：“如果评分器偶尔偏爱错答案，会影响哪个指标？”读者想直接讲就把例子讲完。此时无需同时展开训练算法、所有采样指标和污染检测。

## 阶段收束

在主线、关键推导或一组实验讲完后，简述“现在能解释什么、还有哪个问题”。适合时请读者合上原文画流程、讲机制或推测新场景，然后回原文纠正。后续会话可短暂重建上次关键连接，不固定安排复习天数，不自动创建提醒。

读者要当下理解时不强迫写笔记；需要长期积累时按 session-state.md 形成断点和可复习问题。中途改变目标，更新目标，不重置全部进度。
